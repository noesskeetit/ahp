# Приёмка восстановления исполнения

Запуск из корня репозитория:

```sh
uv venv .venv-recovery
uv pip install --python .venv-recovery/bin/python -e 'sdk/python[dev]'
# AHP_TEST_DATABASE_URL: отдельная тестовая БД PostgreSQL, не рабочая БД стенда.
export AHP_RECOVERY_PYTHON="$PWD/.venv-recovery/bin/python"
node scripts/recovery-process.mjs
```

DSN задаётся через окружение; пример не содержит паролей. Runner требует оба
параметра и завершится с ошибкой при пропуске обязательных тестов. PostgreSQL
должен быть доступен по TCP. Нужны Go с поддержкой `-race`, Python и зависимости
SDK. Тест применяет штатные миграции State и Identity, создаёт таблицу
`public.recovery_effect_receipts` и изолирует сценарии случайными tenant и
experiment ID. БД автоматически не удаляется.

Каждый сценарий запускает отдельный Go-процесс с production State API,
Identity Store и Run Coordinator. Ход создаётся через `Coordinator.AcceptTurn`;
после перезапуска `GetTurn` проверяет холодное чтение его состояния. Также
запускаются отдельные процессы штатного
`python -m ahp_state.container` с LangGraph. Взаимодействие с платформой идёт
по HTTPS с взаимной проверкой сертификатов; CA и ключи генерируются для теста.
Порты выбираются динамически. Убиваются только PID, созданные тестом.

| Сценарий | Проверяемое поведение |
| --- | --- |
| Внешний эффект выполнился, ответ потерян | HTTP-fixture делает **новый** INSERT в PostgreSQL на каждый вызов, затем не отдаёт ACK. После подтверждённого INSERT тест убивает SDK и control plane через SIGKILL. Новый SDK подбирает тот же run с большим epoch и оставляет intent в `unknown`, run — в `waiting/reconcile:effect-0`. Число INSERT остаётся 1. |
| Старый исполнитель и чужой владелец | Запись с прежним fence получает 409; другой subject не читает intent (404). |
| Явная сверка результата | Reconciler использует настоящий ID внешней квитанции, digest и новый lease. После подтверждения SDK завершает тот же run, не вызывая эффект повторно; INSERT всё ещё 1. |
| HITL после истечения JWT | Ожидание переживает перезапуск процесса. Старый токен отклоняется; новый токен того же действующего grant позволяет ответить и продолжить тот же run. Другой subject получает 404. |
| HITL после отзыва grant | Отзыв хранится в реальной Identity DB. Ответ с ранее выданным свежим JWT отклоняется, MintTask не перевыпускает полномочия. Внешних эффектов 0. |
| ACK терминального события потерян | Прокси сначала получает успешный ответ от настоящего State, затем обрывает соединение без передачи ответа координатору. Повтор сохраняет ровно одно терминальное событие. |

Это приёмка протокола восстановления, **не LLM E2E**. LangGraph строится из
поставляемого `examples/billing_agent`, бизнес-операция — намеренно
неидемпотентный HTTP-fixture. Запуск модели здесь не нужен для проверки окна
между внешним эффектом и записью результата. Вход Coordinator аутентифицирован
task JWT; браузерный OIDC flow этой проверкой не покрывается. Истечение токена
проверяется коротким реальным TTL, а не ожиданием нескольких недель.

State lease/inbox/intent/checkpoint и authority находятся в PostgreSQL. Этот
путь SDK не использует Redis; runner не выдаёт Redis ping за проверку очереди.
Dispatcher/Core с Redis требует отдельного интеграционного сценария.

Для диагностики можно установить `AHP_RECOVERY_EVIDENCE_DIR` в приватную
игнорируемую папку: там останутся subprocess logs и временные тестовые
сертификаты/handshake. **Не публиковать эту папку:** private config содержит DSN.
Без этой переменной временная папка очищается Go после теста.

Исторические `tests/chaos/restart.mjs` и `unknown-outcome.mjs` сохранены:
первый проверяет liveness/readiness после SIGKILL; второй — истечение lease,
старый fence и идемпотентность KV. Они не являются доказательством
восстановления внешней бизнес-операции.
