# Адресуемый A2A-собеседник

Продолжение принятого плана завершения PDF rev3.2, рис.18, с.23. Пользователь
поручил автономно довести платформу; дополнительное согласование не требуется.
Работа inline в текущем изолированном worktree, без изменения чужих ресурсов.

1. Registry закрепляет установку, version/config snapshot за текущей
   аутентифицированной задачей Coordinator. Клиент не задаёт version, deployment,
   endpoint или task identity. Повтор возвращает тот же pin; другой ход может
   получить новую опубликованную версию. Проверить реальные PG и HTTP-права.
2. В State turn сохраняется тип исполнителя `a2a` и выбранная установка.
   Привязка к диалогу неизменяема; restore не подменяет её Dot runtime.
   Отдельный исполнитель Coordinator переносит A2A события/статус в транскрипт,
   не запускает Core и не сохраняет внутренние шаги/чекпоинты агента.
3. Gateway/Registry transport сохраняет ключ сообщения, target task и cursor;
   продолжает существующий input-required, обрабатывает cancel/steering и
   восстановление. Контекст агента стабилен между ходами и принадлежит только
   этому сотруднику/диалогу. Нативный runtime сам хранит свою историю и workflow.
4. UI выбирает каталоговую установку для нового диалога. Реальные model/PG/
   restart/HITL/два пользователя проверяются отдельно от протокольных fixtures.
   Обновляются матрица, исходные SKIP и scoped receipts; полная цель остаётся
   активной до доказанного завершения остальных требований.

Нельзя считать разовый Invoke диалогом; подставлять переписку вместо состояния
агента; ослаблять Context ownership; менять выбранный образ уже начатого хода;
сохранять task tokens в State или передавать их браузеру. Существующая рабочая
сборка c44ece62 остаётся на стенде до проверенной замены всех пяти процессов.
