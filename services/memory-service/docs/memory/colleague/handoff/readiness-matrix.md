# Матрица готовности AHP и Agents Space

Обновлено **2 ноября 2026 года**. Основание — присланный PDF **rev3.2, 64 страницы**. Проверенный и опубликованный source: `7c810ec2aa5d0d650205807f6d0e12489fd0fe62`.

**Платформа ещё не закрывает весь документ.** Основные сервисы написаны, отдельные сценарии проверены. Остались недописанные функции, архитектурные расхождения, подключение инфраструктуры и общая приёмка. Основной работающий стенд остаётся на `3c83cf06`: публикация нового кода не означает его развёртывание.

«Доработать» означает изменение продукта; «подключить» — интеграцию и настройку выбранной инфраструктуры; «проверить» — отсутствие достаточного доказательства. Эти виды остатка могут сочетаться. Проверка отдельного блока не означает приёмку всего нового релиза.

Локальная Hindsight-интеграция поверх опубликованного source описана в [MEMORY-UPDATE](../MEMORY-UPDATE.md). Результаты Memory в таблице ниже относятся к проверенному upstream legacy backend; они не переобъявляются приёмкой нового Hindsight backend.

## Agents Space и SDK

| Компонент | Что требуется по документу | Что уже есть | Что осталось |
|---|---|---|---|
| **Граница AS → AHP** | Только API владельцев платформенных данных. | Большинство API-путей существует. | **Исправить отклонение:** `as-runner` напрямую создаёт Artifacts PG/MinIO store и использует Model budget ledger. Перевести на owner API. Укрупнять процессы/деплойменты PDF разрешает; это другой вопрос. |
| **Run Coordinator / Runner / Core** | Зафиксировать запуск и контекст, исполнить агент, доставить поток/итог, отменить или восстановить работу. | Coordinator, runner, durable execution и streaming bridge написаны; Model intents связывают generation с результатом без повторного dispatch. | **Доработать:** полное применение профиля/skills и большие результаты через Artifacts. **Проверить:** весь путь с реальной моделью на одной итоговой версии. Streaming не является отсутствующим компонентом. |
| **as-web** | Чат, история, файлы, прогресс и действия человека. | Адаптированный фронт и выбранные браузерные проверки. | **Доработать и проверить:** пути из соседних строк, direct upload, понятные исходы отмены и общий multi-user сценарий. Экран не доказывает backend-семантику общего чата. |
| **as-profile** | Личные настройки Dot поверх tenant AgentConfig, применяемые в запуске. | Tenant/installation/task config resolution, личные OAuth connections. | **Доработать:** сохраняемый user overlay, объединение с разрешённой конфигурацией, skills и фиксацию применённой версии в run. |
| **as-admin** | Управление агентами, маршрутами моделей, skills, политиками и подключениями tenant. | AgentConfig/lifecycle API и store primitives для ModelRoute/Skill. | **Доработать:** недостающие management API/UI и полный tenant-admin workflow. Метод хранилища ещё не является доступной административной операцией. |
| **as-workspace / общий проект** | Проекты, роли, приглашения; общий чат принадлежит проекту, ход — автору, доступ определяется аудиторией. | Проекты, прямое управление членством и личные subject-owned threads. | **Доработать:** invitation lifecycle и project-owned chat с проверкой участников/аудитории. Общий проект сейчас не означает готовый общий чат по PDF. |
| **AHP SDK / LangGraph Checkpointer** | Платформенные контракты, восстановление, checkpointer и проверка агента перед допуском. | Go/Python SDK, LangGraph saver; реальный LangGraph 0.6.11 участвовал в PG/HTTP/mTLS crash/restart проверках. | **Доработать и проверить:** automatic Artifact spill/hydration, serializer/framework совместимость, полный conformance/startup/CI gate. Checkpointer написан, но весь контракт ещё не закрыт. |

История чата и исполнения относится к **State Store**. **Memory** — долговременные знания, **Workspace** — проекты и версии рабочих файлов, **Artifacts** — байты и производные результаты. Отдельный обязательный Chat History Service не вводится.

| Блок | Что уже есть | Что осталось |

| **Backup/restore, rollout/rollback, HA** | Блок `71632b2b`: холодное восстановление PG/MinIO/Vault/Redis, история/файлы/вход и новый LLM-запуск; sync replica и failover на одном хосте. | **Подключить/проверить:** независимые failure domains, выбранную HA-модель и ротацию сертификатов. | **Tier0 / Tier1 / Tier2A / Tier2B** | Шаблоны и локальный K8s PoC. | **Доработать/подключить/проверить:** keys/storage/limits/egress и границы выбранного tier. Его отдельный повтор 3/3 PASS не заменяет общий успешный прогон. Затем нужны deployment итоговой версии и UI/custom/files/OAuth/Memory/deletion/recovery/load сценарии. [Проверки](checks.md). |

## Очерёдность оставшейся работы

1. API-граница AS/AHP, файловый pipeline, большие checkpoints и tool outputs.
2. Profile, tenant-admin, приглашения и общие чаты; Computer/Browser API и UX при согласованном mock VM.
3. Допуск и установка агентов: SDK conformance, SBOM/подпись, stage/security gates, deploy controller.
4. Инфраструктура выбранного профиля: IAM, mesh, KMS, независимое хранилище; DB/VPC/personal runtime по условиям PDF.
5. Успешный общий check, deployment итоговой версии, пользовательская, отказная и нагрузочная приёмка.
