# AHP прежде Agent Space; личный Dot; SDK Python и Go

Статус: принятое решение пользователя, 3 ноября 2026 года. Основание — прямые уточнения в рабочем диалоге: Dot остаётся личным агентом; текущий фокус переносится на AHP, необходимый для исследований; SDK нужен для Python и Go.

Это уточнение имеет приоритет над прежним планом закрыть одновременно весь PDF rev3.2 и Agent Space. Исходный PDF сохраняется как источник архитектуры; изменение объёма приёмки отмечается явно и не означает выполнения отложенных требований.

## Текущая цель

Рабочий прототип AHP, через который можно установить и запустить собственный агент, вызвать модель и инструмент, сохранить состояние, память и файлы, отменить или восстановить выполнение, проверить права и измерить поведение. Приёмка выполняется через платформенные API и SDK без обязательного интерфейса или Run Coordinator Agent Space.

Backend AHP остаётся на Go. Python нужен как самостоятельный клиентский SDK и для адаптеров Python-фреймворков.

## Обязательный объём SDK

Python и Go — два поддерживаемых SDK с одинаковой семантикой платформенных операций. Наличие библиотеки на одном языке не закрывает требование для другого.

- Покрытие публичных агентских контрактов AHP: авторизация и ограничения полномочий, выполнение, State, Model, Tools, Memory, Artifacts и применимые Workspace/Compute операции.
- Единые схемы ошибок, идемпотентность, отмена, потоки, отзыв доступа, большие данные и восстановление без повторного неизвестного внешнего эффекта.
- Для каждого контракта — таблица Python/Go: реализовано, проверено на реальных сервисах, ограничение или отсутствующая функция. Чужой tenant/subject, отзыв, обрыв/повтор и восстановление проверяются для обоих языков.
- Отдельные исполняемые примеры и инструкции установки для Python и Go. Общие сценарии не должны требовать Agent Space.
- LangGraph saver/checkpointer — адаптер Python SDK. Универсальный Python SDK не привязывается к LangGraph. Необходимость адаптеров ADK и других harnesses определяется отдельным исследованием, а не предположением о едином устройстве checkpoints.

## Граница AHP и Agent Space

| Направление | Решение для текущей работы |
| --- | --- |
| Identity, A2A/Execution, State, Model, Tools/Credentials | Остаются в приёмке AHP. |
| Memory, Artifacts, Workspace | Остаются в приёмке AHP; интегрировать продуктовую модель Memory коллеги и проверять через API/SDK. |
| Registry, Deploy, Evals, Triggers | Остаются в приёмке AHP; пользовательский образ проходит допуск, запуск, обновление и откат. |
| Compute/Computer/Browser | Платформенные контракты и lifecycle остаются. Физические microVM — ранее согласованный MOCK; отдельная доработка экранов Agent Space отложена. |
| SDK Python и Go | Обязательны оба; совместимость и примеры проверяются независимо от Agent Space. |
| Tenant/subject/project isolation, credentials, revoke, deletion, recovery, observability и нагрузка | Остаются обязательными. Личный Dot не делает платформу однопользовательской и не отменяет проверки доступа. |
| Dot | Личный агент. Общий Dot больше не является целью текущей продуктовой модели. Это не решение о выделенном процессе или VM на каждого пользователя. |
| Общие чаты, приглашения и прочие новые функции Agent Space | Отложены; не блокируют приёмку AHP и не помечаются реализованными. |
| Профиль, админка и существующий frontend Agent Space | Сохранить существующую работу. Не расширять ради приёмки AHP; допустимы как необязательный клиент или источник регрессионных проверок. |
| Run Coordinator и Core Dot | Компоненты Agent Space. Их завершённость не подменяет проверку AHP и не требуется для самостоятельного платформенного сценария. |

## Исследования

Исследования SDK/checkpointers, совместимости и размещения Codex, pi, harness^2, Hermes, ADK, LangGraph и custom harnesses остаются отдельным потоком. Сравнивать контракты, необходимые адаптеры, объём изменений и ограничения, фиксируя выводы в подводных камнях. Не объявлять поддержку по одному успешному запуску или наличию HTTP endpoint.

Начинать исследование по мере готовности нужного платформенного контракта; завершённость Agent Space не является условием. Эксперименты с sandbox/microVM и Google Substrate сохраняются отдельно от mock-приёмки AHP. Substrate остаётся исследовательским сайдквестом, а не обязательной зависимостью реализации.

## Правила статуса

В матрице отдельно показывать AHP, SDK Python, SDK Go, Agent Space и исследования. Для Agent Space использовать «отложено решением пользователя», для общей модели Dot — «изменено решением пользователя», а не PASS. Готовность AHP не называть завершённостью исходного PDF целиком. Синтетические Cloud IAM/KMS/BYOK и физические microVM MOCK остаются явно обозначенными исключениями.
