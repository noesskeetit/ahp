# Матрица остатка: at-rest crypto — закрыто / синтетика / отложено

Блок at-rest-crypto. Статус: принят директором, ставится в очередь на слияние. Уровень доказательств — локальный изолированный стенд lane (реальные PG/MinIO/Redis), НЕ production/HA/живой вендорский KMS. Ничего ниже не выдаётся за живую интеграцию.

## A. ЗАКРЫТО (реализовано и доказано на изолированном стенде lane)

- Envelope-шифрование содержимого: AES-256-GCM + HKDF-SHA256 (stdlib), без самодельной крипты. Аутентифицированное шифрование; подмена/повреждение байта → отказ.
- Строгая привязка tenant/keyID/version/purpose через AAD обоих слоёв; wrong-tenant → отказ изоляции, wrong-key/purpose/tamper → отказ аутентификации (доказано тестами).
- Fail-closed: нет активного ключа/авторитета → отказ записи; disabled/revoked версия → отказ чтения; malformed → отказ до обращения к ключу; защита от giant-alloc на подделанной длине.
- Ротация читает предыдущие версии; restart/новое соединение читает ранее sealed-данные при том же профиле оператора.
- Двойное чтение: старые plaintext-объекты/строки читаются, новые пишутся шифрованными; `encryption_mode` + самораспознавание envelope (обратимо-совместимо).
- Объектный байт-шов Artifacts (`internal/atrest/objectcipher`) с операторским включателем `AHP_ATREST_ARTIFACTS_ENABLED` (default OFF). OFF доказан инертным (объект байт-в-байт plaintext, без envelope-магии, silent-enable нет); ON сохраняет sha256/dedup-идентичность и range-эквивалентность, читает legacy-plaintext.
- Формат-дефект исправлен: 4-байтные длины (Seal работал только до 64 KiB на прежнем 2-байтном снапшоте), регресс `TestLargePayloadRoundtrip`. Принятый снапшот суперсидится.

## B. СИНТЕТИКА (разрешённое упрощение; НЕ выдаётся за внешний/живой контур)

- КМС: `SYNTHETIC` — `SyntheticKeyManager`, ключи-авторитет в процессе оператора (Tier0 root-вывод / Tier1 BYOK из приватного файла). Это НЕ вендорский KMS. Реальный KMS (Vault transit / облачный) = внешний prerequisite, см. C-R5.
- Стенд: изолированные PG/MinIO/Redis lane (host.docker.internal); TLS/сеть между сервисами и физическое шифрование этих томов НЕ измерялись этим блоком.
- Объектный шов готов как механизм; фактический монтаж в write-path Artifacts (presigned-upload transform, сегментный decrypt) ещё НЕ выполнен — это за Artifacts-владельцем (Galileo).

## C. ОТЛОЖЕНО (отдельные незакрытые требования; внешний prerequisite или контракт другой lane)

| # | Незакрытое требование | Почему отдельно | Владелец | Что нужно для закрытия |
|---|---|---|---|---|
| R1 | Метаданные/дайджесты/пути plaintext: `sha256/expected_sha/size`, `*_digest`, `labels/provenance/evidence`, пути/имена объектов и workspace-дерева, пути Vault | Участвуют в seal/дедуп/range/поиске/идемпотентности — generic envelope их ломает; нужна отдельная схема защищённых поисковых метаданных | Artifacts + State + Workspace | RFC на protected searchable metadata; что остаётся видимым по дизайну |
| R2 | Memory `search tsvector` и `embedding vector(N)` утекают содержимое даже при шифровании `text` | Индекс/вектор выводятся из текста; шифрование `text` ломает полнотекстовый поиск и ANN; семантику поиска менять нельзя | Memory | Blind index / encrypted ANN с сохранением recall/rerank; приёмочный корпус поиска |
| R3 | Нативный Hindsight `ahp_longterm.memory_records.body jsonb` plaintext | Собственный продукт-контракт Memory-хранилища; шифровать молча из крипто-блока нельзя | Memory | Встроить envelope без изменения extraction/recall (Stage 3 RFC) |
| R4 | Физическое шифрование томов/носителей бэкапов и резидентность Tier 2A/2B | Свойство инфраструктуры/размещения, не библиотеки; из кода не проверяется | Инфраструктура (root/mac-director) | Средовые доказательства volume/backup encryption, Tier2A customer PG/S3/KMS, Tier2B локальная ячейка |
| R5 | Реальный вендорский KMS (Vault transit / облачный KMS) вместо `SYNTHETIC` | `SyntheticKeyManager` — разрешённая синтетика; внешний KMS = внешний prerequisite с другим API, HA и секретами провайдера | Инфраструктура + hive-director | Подключить `KeyAuthority` к реальному KMS, проверить rotate/disable/revocation через провайдер |
| R6 | Фактический монтаж объектного шва в write-path Artifacts + сегментный decrypt больших объектов | Меняет клиентский контракт загрузки/скачивания и потребление памяти (сейчас полный read+slice, пик ~2× на 32 MiB) | Artifacts (Galileo) | Подключить `objectcipher` к presigned/put/get точкам; стриминговый decrypt; RFC §6 |

Правило чтения: раздел A — принято; раздел B — работает, но это синтетика/механизм, а не живой контур; раздел C — открытые требования, ни одно из них не закрыто и не должно приравниваться к принятому результату.
